# AGENTS.md — правила работы в HopBeer

Проект: Django-приложение для базы данных пива, хмеля, производителей и оценок.
Точка входа: `manage.py`, проект `beer_app`, приложение `brewery`.

## Главное правило: сначала спека, потом код

1. Прочитай `specs/constitution.md` — рамка решений.
2. Найди спеку задачи в `specs/` (baseline — `specs/000-baseline/spec.md`).
   Если спеки нет — создай её:

   ```powershell
   .venv\Scripts\python.exe scripts/new_spec.py --title "Краткое название изменения"
   ```

3. Заполни `spec.md`: проблема, требования `FR-*`, критерии приёмки `AC-*`,
   влияние на baseline. Затем `plan.md` и `tasks.md`.
4. Реализуй задачи, отмечая их в `tasks.md` только после проверки.
5. Обнови спеку, если по ходу выяснилось, что требования были неполными.

Не меняй поведение «молча»: любое изменение пользовательского поведения должно
быть видно в спеке и в диффе тестов. Опечатки, форматирование и обновление
зависимостей без изменения поведения — можно без спеки.

## Команды

Окружение — `.venv` в корне проекта (Windows).

```powershell
# тесты (DEBUG=True нужен, чтобы не требовался DJANGO_SECRET_KEY)
$env:DJANGO_DEBUG = 'True'
.venv\Scripts\python.exe manage.py test

# проверка конфигурации
.venv\Scripts\python.exe manage.py check

# миграции
.venv\Scripts\python.exe manage.py makemigrations
.venv\Scripts\python.exe manage.py migrate

# запуск
$env:DJANGO_DEBUG = 'True'
.venv\Scripts\python.exe manage.py runserver
```

Прод-запуск, systemd, Caddy и media — см. `docs/DEPLOYMENT.md`.

## После реализации фичи

После реализации любой фичи всегда перезапускай локальный Django-сервер, даже
если `runserver` обычно автоматически перезагружает код. Останови старый процесс,
запусти сервер заново по команде выше и проверь, что он отвечает на локальном
адресе, прежде чем завершать задачу. Это правило относится только к локальному
серверу; production-сервер без отдельного запроса не перезапускай.

## Конвенции кода

- Python 3.11+, Django 5.0. Модели — в `brewery/models.py`, формы —
  `brewery/forms.py`, представления — `brewery/views.py`, маршруты —
  `brewery/urls.py`, шаблоны — `brewery/templates/brewery/`, стили — `static/css/`.
- Представления — class-based (`LoginRequiredMixin` + generic views), формы —
  `ModelForm`, шаблоны наследуют `brewery/base.html`.
- Все разделы, кроме главной, требуют аутентификации. Изменять каталог (пиво,
  хмель, производителей) могут только пользователи с `is_staff=True`; оценки
  изменяет и удаляет только их владелец. Владелец новой оценки берётся из
  `request.user`.
- Пользовательские тексты и комментарии в коде — на русском. Локаль `ru-ru`,
  десятичный разделитель — запятая.
- Соцвход — только через `django-allauth`. Ключи провайдеров (`YANDEX_CLIENT_ID`,
  `YANDEX_CLIENT_SECRET`) берутся только из окружения; тексты страниц входа и
  связей живут в шаблонах проекта (`brewery/templates/account/`,
  `brewery/templates/socialaccount/`), потому что `brewery` стоит в
  `INSTALLED_APPS` раньше allauth.
- Валидация — на сервере (в форме/модели), а не только атрибутами HTML.
- Не трогай `db.sqlite3`, `media/`, `staticfiles/`, `server*.log` — это
  локальные/сборочные артефакты, они вне git.

## Тесты

- Тесты живут в `brewery/tests.py`; при росте — пакет `brewery/tests/`.
- На каждый `AC-*` — тест; имя теста отражает поведение, а не класс.
- Для статики в тестах используется `TEST_STORAGES` (см. `brewery/tests.py`):
  в проде манифест WhiteNoise, в тестах — обычное хранилище.
- Запускай тесты перед завершением задачи и прикладывай результат в отчёт.

## Git

- Ветка от `master`, имя начинается с `kodik/`, например
  `kodik/spec-001-beer-search`.
- Коммиты: `spec(SPEC-003): ...`, `feat(SPEC-003): ...`, `fix(SPEC-001): ...`.
- Не коммить секреты, БД, медиа и логи. Не переписывай чужие незакоммиченные
  изменения.

## Карта репозитория

```
beer_app/      настройки проекта, корневые URL
brewery/       приложение: модели, формы, CBV, шаблоны, тесты
docs/          эксплуатационная документация
scripts/       служебные скрипты (импорт, создание спек)
specs/         конституция, спеки, шаблоны, бэклог
static/        CSS и статические изображения
```
