## 1. Назначение

Спека фиксирует поведение приложения **как оно реализовано сейчас**, а не как
хотелось бы. Это точка отсчёта для всех будущих изменений: новая спека обязана
явно указать, какие требования ниже она меняет. Расхождения, найденные при
описании, вынесены в раздел 8 и не считаются «уже сделанными».

Читать вместе с `specs/constitution.md`. Ссылки на код даны для проверки, но
требования описаны через поведение.

## 2. Роли и доступ

| Роль | Определение | Доступ |
|---|---|---|
| Гость | не аутентифицирован | главная страница, форма входа |
| Пользователь | аутентифицирован через `django.contrib.auth` | все разделы, CRUD, свои оценки, отчёт |
| Администратор | `is_staff`/`is_superuser` | Django admin |

**FR-001.** Все разделы приложения, кроме главной, требуют аутентификации
(`LoginRequiredMixin` в `brewery/views.py`). Гость, открывший защищённую
страницу, получает редирект на `/accounts/login/?next=<исходный URL>`.
Страницы входа и восстановления пароля публичны; `/admin/` доступен только
staff-пользователям.

**FR-002.** Вход и выход — стандартные представления `django.contrib.auth`
(`/accounts/login/`, `/accounts/logout/`, смена пароля и т.д.,
`beer_app/urls.py:13`). Выход выполняется POST-формой с CSRF-токеном
(`brewery/templates/brewery/base.html:31`).

Модели — `brewery/models.py`. Схема хранится в SQLite (`db.sqlite3`), миграции —
`brewery/migrations/`.

## 4. Функциональные требования

### 4.1 Производители, хмель, пиво

**FR-003.** Для производителей, хмеля, пива и оценок доступны списки, создание,
редактирование и удаление через веб-интерфейс (`brewery/urls.py`):

| Сущность | Список | Создание | Редактирование | Удаление |
|---|---|---|---|---|
| Производитель | `/vendors/` | `/vendors/create/` | `/vendors/<pk>/edit/` | `/vendors/<pk>/delete/` |
| Хмель | `/hops/` | `/hops/create/` | `/hops/<pk>/edit/` | `/hops/<pk>/delete/` |
| Пиво | `/beers/` | `/beers/create/` | `/beers/<pk>/edit/` | `/beers/<pk>/delete/` |
| Оценка | `/ratings/` | `/ratings/create/` | `/ratings/<pk>/edit/` | `/ratings/<pk>/delete/` |

После успешного создания, изменения и удаления пользователь возвращается на
список соответствующего раздела. Удаление требует подтверждения на отдельной
странице.

**FR-004.** Пиво имеет страницу просмотра `/beers/<pk>/` с полями, картинкой,
производителем и хмелем. Блок оценок на этой странице не выводится: средняя
оценка и своя оценка видны в списке пива (FR-011).

**FR-005.** В форме пива хмель выбирается множественно. Значения передаются
скрытым полем и сохраняются в M:N через `BeerForm.save()`; на странице формы
список хмеля доступен для виджета выбора (`hops_json`). При редактировании
текущий набор хмеля подставляется в начальные значения.

### 4.2 Картинки

**FR-006.** Картинка пива необязательна. Если файл загружен и читается как
изображение, при сохранении он приводится к RGB, уменьшается до 800 px по
длинной стороне и сохраняется как JPEG с качеством 82. Если файл не читается,
сохранение не прерывается — файл остаётся как есть.

**FR-007.** Если у пива нет картинки, в списке и на странице пива показывается
заглушка `static/img/beer-placeholder.svg`.

### 4.3 Оценки и их видимость

**FR-008.** При создании оценки владелец всегда берётся из `request.user`; поле
владельца не показывается в форме и не может быть задано пользователем.

**FR-009.** Ссылка «Оценить» из списка пива ведёт на `/ratings/create/?beer=<pk>`
и предзаполняет форму выбранным пивом. Если параметр не число, предзаполнения
нет.

**FR-010.** Страница «Оценки» (`/ratings/`) показывает **только оценки текущего
пользователя** и сообщает общее количество оценок всех пользователей в базе
(«всего в базе: N»). Если у пользователя оценок нет, показывается «У вас пока
нет оценок».

**FR-011.** В списке пива для каждого пива показываются:
- средняя оценка по **всем** пользователям с точностью до одного знака
  (`floatformat:"-1"`: `6,5`, но `8` без десятичной части) и общее количество
  оценок;
- если оценок нет — «Оценок пока нет»;
- если у текущего пользователя есть оценка — «Моя оценка: X/10» и ссылка
  «Изменить оценку»;
- если своей оценки нет — ссылка «Оценить» с предзаполнением пива.

**FR-012.** Главная страница (`/`) доступна без входа и показывает карточки
разделов со счётчиками:

| Счётчик | Значение |
|---|---|
| Пиво | все записи |
| Хмель | все записи |
| Производители | все записи |
| Оценки | для гостя — все оценки; для пользователя — только его |
| Отчет | константа `REPORT_TABLE_COUNT = 2`, выводится как «2 отчетов» |

### 4.4 Отчёт

**FR-013.** Страница «Отчет» (`/reports/`) требует аутентификации.

**FR-014.** Таблица «Самые вкусные хмели»: до 5 хмелей, у пива которых есть
оценки. Средняя оценка — по всем оценкам всех пив с этим хмелем. Сортировка:
средняя оценка по убыванию, затем количество пив с этим хмелем по убыванию,
затем название по возрастанию. Колонки: хмель, популярность (количество пив),
средняя оценка, пример — лучшее по средней оценке пиво этого хмеля (при равной
средней — по названию). Если оценённого пива с хмелем нет — «Пока нет оценённого
пива с хмелем».

**FR-015.** Таблица «Самые популярные производители»: до 5 производителей, у
которых есть хотя бы одно пиво. Сортировка: количество пив по убыванию, затем
средняя оценка по убыванию (без оценок — в конце), затем название. Если пива с
производителем нет — «Пока нет пива с указанным производителем».

### 4.5 Админка и локализация

**FR-016.** В Django admin зарегистрированы все четыре модели. Для пива —
inline оценок и горизонтальный выбор хмеля; у производителей, хмеля и пива есть
поиск, у пива — фильтры по стилю и производителю.

**FR-017.** Интерфейс на русском, `LANGUAGE_CODE = 'ru-ru'`,
`TIME_ZONE = 'Europe/Moscow'`. Числа с дробной частью выводятся с запятой.
Названия разделов: «Пиво», «Хмель», «Производители», «Оценки», «Отчет».

## 6. Нефункциональные требования

- **NFR-001. Стек.** Django 5.0, SQLite, серверный рендеринг, WhiteNoise,
  gunicorn, Caddy. Без SPA и внешней БД.
- **NFR-002. Конфигурация.** `DEBUG=False` по умолчанию; `SECRET_KEY` и
  `ALLOWED_HOSTS` — из окружения; без `DJANGO_SECRET_KEY` при `DEBUG=False`
  приложение не стартует (`beer_app/settings.py:14-26`).
- **NFR-003. Безопасность.** CSRF включён, logout только POST; защищённые
  страницы требуют входа; `SECURE_PROXY_SSL_HEADER` настроен под reverse-proxy.
- **NFR-004. Логи.** Только stdout/stderr; на сервере собираются journald
  (`journalctl -u hopbeer`). Приложение пишет через логгер `brewery`.
- **NFR-005. Статика и медиа.** В проде статика через WhiteNoise с манифестом;
  `media/` отдаётся Caddy; в dev — через `static()` при `DEBUG=True`.
- **NFR-006. Объём данных.** Ожидается небольшая локальная база; пагинация и
  полнотекстовый поиск сейчас не реализованы (см. раздел 8).

## 7. Вне области baseline

- REST/JSON API, мобильное приложение, интеграции.
- Многопользовательские рабочие пространства и роли, кроме staff/superuser.
- Уведомления, экспорт, импорт (скрипт `scripts/import_beers_2026_09.py` —
  вспомогательный, не часть веб-приложения).
- Публичный просмотр чужих оценок и рейтингов пользователей.

## 8. Известные расхождения и долги

Это не «сделано», а зафиксированные разрывы между текущим кодом и принципами
проекта. Каждый пункт — кандидат в отдельную спеку (см. `specs/backlog.md`).

1. **Нет серверной проверки владельца при изменении и удалении оценки.**
   `RatingUpdateView` и `RatingDeleteView` (`brewery/views.py:171-181`) работают
   со всеми оценками: любой аутентифицированный пользователь может открыть
   `/ratings/<pk>/edit/` или `/ratings/<pk>/delete/` для чужой оценки и изменить
   её, включая поле «пиво». Нарушает конституцию, V. → BL-01.
2. **Оценка 1–10 не валидируется на сервере.** Ограничение задано только
   атрибутами `min`/`max` в HTML (`brewery/forms.py:84`); модель принимает
   `PositiveSmallIntegerField` (`brewery/models.py:131`), то есть 0 и значения
   больше 10 проходят. → BL-01.
3. **Дубликаты оценок.** Нет ограничения уникальности `(beer, owner)`, поэтому
   один пользователь может оценить одно пиво несколько раз. В списке
   показывается `my_ratings.0` (`beer_list.html:39`) — неоднозначно. → BL-02.
4. **Оценки без владельца.** `owner` nullable (`brewery/models.py:123-130`):
   такие записи не видны ни одному пользователю в разделе «Оценки» и не
   учитываются в его счётчике, но влияют на средние. → BL-02.
5. **Пережатие картинки при каждом сохранении.** `Beer.save()`
   (`brewery/models.py:96-110`) обрабатывает `self.image.file` при любом
   сохранении, включая правку текстовых полей; возможна повторная потеря
   качества и лишние файлы. → BL-04.
6. **Нет пагинации и поиска.** Списки отдают все записи (`ListView` без
   `paginate_by`), фильтров нет. → BL-03.
7. **Средние в отчёте считаются по всем пользователям**, хотя раздел «Оценки»
   персонален. Это осознанное решение, зафиксировано в FR-014/FR-015; если нужен
   «мой» отчёт — это новая спека.
8. **Захардкоженная плюрализация.** «2 отчетов» в `index.html:13` и
   `REPORT_TABLE_COUNT` в `brewery/views.py:186` не зависят от числа таблиц.
   → BL-05 (косметика).
9. **Неравномерное покрытие тестами.** Покрыты список пива, видимость оценок и
   отчёт; AC-001, AC-021…AC-024 и AC-026 не покрыты. → BL-06.
10. **Права в админке.** Модели доступны всем staff-пользователям без
